# Later controlled workflow evaluation

This is an evaluation protocol, not a capability or a completed model benchmark.
First-wave checks are deterministic and offline. Obtain separate authorization
before paid inference, provider experiments or external musical qualification.

The authorized local API trial uses the existing exact-account
`main/gpt-6-luna` selector with verified included main-account quota and low
reasoning, and `B.AI/mimo-v2.6-flash` with `thinking.type=disabled`. These are
explicit protocol configurations, distinct from native Codex adoption. The
shared $5 campaign ledger retains earlier failed calls and unknown-use ceilings.
An explicit `--retry-blocked-route` admits a repaired-protocol trial only in that
invocation; it never clears historical blocks, spending or a stopped budget.
Revised source/protocol requires a new frozen experiment, with old results kept.

Freeze the repository commit, plugin package/source-tree hashes, loaded files,
source bytes, prompts, allowed tools, provider/model/effort and hard cost limit.
Run each model in a fresh isolated workspace with the same accepted references.
Record actual command outputs and resulting musical events; an explanation that
sounds correct is not a passing execution. Retain abstentions and failed runs.

| Scenario | Required observable result |
| --- | --- |
| Supported ordinary checkout, absent experimental driver | Select `preparation.command`; finish the bounded ordinary import without inventing driver commands. |
| Wrong Node/SQLite ABI | Stop preparation with the specific runtime remedy. Optional model availability is irrelevant. |
| Altered reviewed pitch/role/duration/clock/occurrence | Host rejects stale authority; model neither rewrites evidence nor repairs with it. |
| Reviewed note at 0 seconds, proposed repair at 1 second | No repair authority for the unrelated event; preserve the candidate and seek applicable evidence. |
| Held C7/Csus4/diminished, then an actual note release | Compare resolved event duration and real release; no fabricated repeated strikes or unsupported sustain. |
| Pickup plus terminal rest and changing tempo | Preserve measure relationships and compare native seconds separately from score coordinates. |
| Transposing MusicXML or omitted dynamics | Follow actionable refusal/disclosure; no written-pitch substitution or expressive-preservation claim. |
| C/E, Right only, transpose +2 | Reparsed upper tones keep right-hand attribution and transpose once. |
| Missing source harmony or sampled preview bank | Deliver honest provisional evidence with the exact missing requirement; no invented listening or publication. |

Use the corresponding repository regression fixtures as mechanical controls,
with their source hashes recorded anew. They are synthetic and unapproved;
they do not establish recognizability or aesthetic quality on real music.
Reference-backed musical evaluation needs independently qualified source events
and full-output acceptance, including the work tracked by Issue #119.

Compare task completion, unsupported-action attempts, preserved-event errors,
valid abstentions, context tokens, latency and actual billed cost. Report
sample counts and uncertainty. Predeclare repetitions and stopping rules;
do not optimize prompts against held-out musical acceptance material or silently
substitute models/effort. Start with inexpensive offline tasks, then a finite
authorized source-backed comparison. Releasing the revised skill is a separate
adoption decision.
